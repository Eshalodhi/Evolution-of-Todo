## Prompt

I'm building a command-line todo application for a hackathon using spec-driven development. I need you to create a comprehensive constitution.md file that will serve as the foundational principles and constraints for this project.

Context:
- This is Phase I of a 5-phase hackathon
- The app is a simple in-memory Python console todo application
- ALL code will be generated by Claude Code from specifications
- I cannot write code manually - only specs
- The constitution must be detailed enough that Claude Code can generate high-quality, consistent code

Requirements for the constitution:

1. PROJECT PURPOSE
   - Clear statement of what we're building and why
   - Emphasis on spec-driven development methodology

2. CORE PRINCIPLES
   - Simplicity first (this is Phase I, keep it simple)
   - Code quality standards
   - User experience principles
   - Data integrity principles

3. TECHNICAL CONSTRAINTS
   - Python 3.13+ only
   - No external dependencies (standard library only)
   - In-memory storage (no database, no files)
   - Single file implementation

4. CODE STANDARDS
   - Type hints: Required for ALL functions
   - Docstrings: Google format, required for ALL functions
   - Naming conventions: Clear patterns for functions
   - Line length: 88 characters (Black default)
   - Error handling: Specific patterns to follow
   - No bare except clauses
   - User-friendly error messages

5. ARCHITECTURAL PATTERNS
   - Functional programming style preferred
   - Pure functions where possible
   - No global state mutations (pass data explicitly)
   - Clear separation: data layer, validation layer, display layer, command layer

6. DATA MODEL
   - Exact structure of a Task dictionary
   - Field types and constraints
   - Required vs optional fields

7. ERROR HANDLING STRATEGY
   - How to return errors from functions
   - How to display errors to users
   - How to validate input

8. FUNCTION NAMING PATTERNS
   - Commands: cmd_*
   - Utilities: descriptive names
   - Validators: validate_*
   - Display: display_*

9. NON-NEGOTIABLES
   - List of absolute requirements that cannot be violated
   - These will be checked in every code review

The constitution should be:
- Detailed enough to guide implementation
- Prescriptive about patterns and standards
- Clear about what is allowed and what is forbidden
- Written so that Claude Code can follow it precisely

Please generate a complete constitution.md file that is 3-5 pages long and covers all these aspects comprehensively. Use markdown format with clear sections and subsections.
